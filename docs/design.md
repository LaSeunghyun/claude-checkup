# Claude 설정 점검 (claude-checkup) 설계 v2

작성 2026-11-01. v1(사용 현황 지도 중심)을 사용자 피드백으로 고쳐 쓴 판이다.
브레인스토밍 시안: checkup-result-v10(검진 결과지·연결 지도), fix-preview-v11(고치기 미리 보기), hearth-map-modal-v8, agents-drilldown-v9. 모두 Hearth DS.

## 1. 왜 만드나

Claude Code에 스킬·에이전트·메모리·훅·플러그인을 몇 달 쌓으면 세 가지를 알 수 없게 된다.

1. 만든 것이 실제로 의도대로 쓰이는가.
2. 같은 규칙이 겹치거나, 길어서 잘리거나, 연결이 끊겨 동작하지 않는 곳이 있는가.
3. 쓰지 않는데 매 대화 컨텍스트를 차지하는 것이 있는가.

v1 화면(사용 현황 지도)을 본 사용자의 반응은 "그래서 뭘 하라고?", "이게 뭔데?", "Claude에게 점검해 달라는 것과 뭐가 달라?"였다.
그래서 v2는 데이터를 보여 주는 화면이 아니라 할 일을 알려 주고, 직접 고치고, 효과를 재는 도구로 바꾼다.

Claude에게 묻는 것과 다른 점은 세 가지다. 이 셋이 화면에서 보여야 한다.
- 근거: 몇 달 치 실제 대화 기록(이 PC 기준 3.37GB, 약 8억 토큰 분량)을 AI 없이 세서, 토큰 0으로 몇 초 안에 판단한다. Claude는 이 기록을 다 읽을 수 없어 추측하게 된다.
- 미리 보기가 있는 고치기: 바뀌는 내용과 기대 효과(좋아지는 것과 치르는 것)를 계산값으로 먼저 보여 주고, 적용하면 백업하고 되돌릴 수 있다.
- 전후 비교: 고친 뒤 같은 기준으로 다시 재서 무엇이 얼마나 줄었는지 보여 준다.

대상은 AI에 익숙하지 않은 Claude Code 사용자다. 누구나 받아 쓰는 공개 도구로 낸다.

## 2. 목표, 비목표, 반목표

목표
- 첫 화면 = 검진 결과지: 판정 한 줄, 위험, 효과 큰 순서의 할 일 3개, 전후 비교.
- 고치기: 할 일마다 미리 보기 → 적용 → 다시 점검 → 전후 비교 → 되돌리기.
- 연결 지도: md 파일이 출발점에서 어떻게 이어지는지와 연결 누수.
- 둘째 화면: 전체 진단, 사용 현황 지도(v1 지도), 항목 모달, 검색. v1 구현을 재사용한다.
- 실행: 단일 실행 파일을 더블클릭하면 로컬 서버가 뜨고 브라우저가 열린다.

비목표 (이번 판)
- Codex, Cursor 등 다른 도구.
- 사용자 고유 하네스(triggers.json 등) 해석. Claude Code 표준 구조만 읽는다.
- 라우팅 시험("AI가 제때 골라 쓰나요?"). 고치기와 같은 `claude -p` 실행기를 쓰므로 그 위에 다음 판에서 붙인다. 화면에는 자리를 두지 않는다.
- 여러 할 일을 한 번에 묶어 적용하기. 할 일 하나에 미리 보기 하나다.
- 익명 통계를 받는 서버. 앱 쪽 전송 장치만 둔다(8-2절).

반목표 (이러면 실패)
- 미리 보기 없이 설정을 바꾼다. 백업 없이 바꾼다.
- 플러그인 폴더 안의 파일을 고친다(업데이트 때 덮어써진다).
- 비밀값(토큰, 키)을 읽어서 화면·결과·로그·`claude -p` 요청문에 싣는다.
- 고치기 외의 기능이 PC 밖으로 무언가를 보낸다. 고치기는 Claude에게 파일 내용을 보내므로 처음 쓸 때 알리고 동의를 받는다.
- 앱이 돌린 `claude -p` 가 대화 기록에 남아 다음 점검 숫자를 오염시킨다.
- 근거 없는 숫자를 단정한다. 추정치는 "약", "추정"으로 표시한다.

## 3. 용어 (화면 표기)

그대로 쓰는 말: 에이전트, 메모리, 하네스, 컨텍스트, .claude, CLAUDE.md, MEMORY.md, 플러그인.
바꿔 쓰는 말: 스킬 = 작업 설명서, 훅 = 자동 실행 규칙, MCP 서버 = 연결된 서비스, 토큰 = A4 몇 쪽(추정), 슬래시 명령 = 직접 부르는 명령.
모달 위쪽에 "원래 이름: 스킬(Skill)"처럼 원래 용어를 작게 남긴다.
용어가 처음 나오는 곳에는 한 줄 설명을 붙인다(예: "작업 설명서: Claude가 특정 일을 할 때 꺼내 보는 설명서예요").
어투는 해요체. 진단 문구에 "이(가)", "을(를)" 같은 기계식 조사를 쓰지 않는다.

## 4. 데이터 출처 (읽기 전용)

`HOME` = 사용자 홈. `C` = `HOME/.claude`.

| 대상 | 위치 |
|---|---|
| 전역 지시문 | `C/CLAUDE.md` 와 그 안의 `@경로` import |
| 프로젝트 지시문 | `HOME/.claude.json` 의 `projects` 키 경로 중 실제 있는 폴더의 `CLAUDE.md`, `AGENTS.md` |
| 메모리 | `C/projects/*/memory/MEMORY.md` 와 같은 폴더 `*.md`, `C/memory/*.md` |
| 개인 스킬 | `C/skills/*/SKILL.md` |
| 개인 명령 | `C/commands/*.md` |
| 개인 에이전트 | `C/agents/*.md` |
| 플러그인 | `C/plugins/installed_plugins.json` 의 `installPath`, 켜짐 여부는 `C/settings.json` 의 `enabledPlugins`. 플러그인 안 `skills/*/SKILL.md`, `commands/*.md`, `agents/*.md`, `hooks/hooks.json`, `.mcp.json` |
| 훅 | `C/settings.json` 의 `hooks`, 플러그인 `hooks/hooks.json` |
| 연결된 서비스 | `HOME/.claude.json` 의 `mcpServers`(전역)와 `projects.*.mcpServers`, 플러그인 `.mcp.json`. 이름만 읽고 `env`, `headers`, `args`, `url` 값은 읽지 않는다 |
| 기본 제공 에이전트 | 고정 목록: general-purpose, Explore, Plan, statusline-setup, claude-code-guide |
| 기록에만 있는 항목 | 최근 30일 기록에 쓰인 작업 설명서·에이전트 이름 중 위 어디에도 파일이 없는 것. 출처 `history`("기록에만 있음"). 기본 내장, 지운 것, 이름이 바뀐 것을 가르지 않는다. `플러그인:이름` 꼴은 만들지 않는다 |
| 대화 기록 | `C/projects/**/*.jsonl` (하위 `subagents/` 포함) |

이름에 `credential`, `token`, `secret`, `auth`, `password`, `passwd`, `apikey`/`api_key`, 단어 `pat`, `.env`, `.pem`, `.key` 가 들어간 파일은 열지 않는다.
읽은 글은 화면·결과·요청문에 싣기 전에 늘 비밀값 가리기(`redactSecrets`)를 거친다. 예외 없음.

## 5. 측정 정의

기간: 실행 시점 기준 최근 30일. 대화 기록 줄의 `timestamp` 로 거른다.
줄은 부분 문자열로 먼저 거른 뒤 해당 줄만 `JSON.parse` 하고, 스트리밍으로 읽는다.
재개된 대화는 이전 기록을 복사해 오므로, 사건마다 id(tool_use id, 줄 uuid)로 중복을 거른다. 훅 기록도 줄 `uuid` 로 거른다.

| 지표 | 정의 |
|---|---|
| 스킬 사용 | `type=tool_use`, `name=Skill` 의 `input.skill`. `via.model` |
| 직접 부름 | 사용자 메시지 안 `<command-name>/이름</command-name>`. `via.user`. 스킬 펼침 메타 줄은 세지 않는다 |
| 에이전트 사용 | `name` 이 `Agent`/`Task` 인 tool_use 의 `input.subagent_type`(없으면 general-purpose) |
| 연결된 서비스 사용 | `name` 이 `mcp__<서버>__<도구>` 인 tool_use |
| 파일 읽힘 | `name=Read` 의 `input.file_path`. 소문자·슬래시로 맞추고 `/.claude/` 뒤 부분으로 매칭 |
| 훅 실행 | `attachment.type` 이 hook 으로 시작하는 줄의 `command`, `durationMs`, `exitCode`. 설정의 훅 command 와 매칭(플러그인 훅의 `${CLAUDE_PLUGIN_ROOT}` 는 설치 경로로 펼쳐 맞춘다) |
| 훅 실패 | 종료 코드가 0도 2도 아닌 실행, 또는 type 에 error 가 든 줄. 종료 코드 2와 blocking 계열은 "막음"(의도한 동작)으로 따로 센다 |
| 훅이 넣은 양 | `hook_additional_context` 의 `content` 글자 수, `hookEvent` 별 평균 |
| 대화 수 | 30일 안에 줄이 있는 jsonl 파일 수(subagents 제외) |
| 요청 수 | `type=user` 이고 도구 결과·compact 요약·`!` 셸 입력이 아닌 사용자 메시지 수 |

Claude Code 는 성공한 훅 실행을 다 기록하지 않는다. 그래서 훅 실행 수는 "기록에 남은 실행"이라고 표시하고 실패율은 내지 않는다.
캐시: 파일 경로별 `mtime`·`size` 가 같으면 지난 집계를 다시 쓴다. `HOME/.claude-checkup/cache.json`.

### 컨텍스트 추정

토큰 추정 = `ceil(ASCII 글자 수 / 4 + 비ASCII 글자 수 / 1.5)`. A4 1쪽 = 1,500 토큰(추정). 컨텍스트 전체 = 200,000 토큰.

대화마다 미리 채워지는 것
- 전역 CLAUDE.md 본문 + import 본문.
- MEMORY.md 앞 200줄. 프로젝트마다 따로 있고 한 대화에는 하나만 실리므로 합계에는 가장 큰 하나를 쓴다.
- 켜진 스킬·명령마다 목록 한 줄 `- 이름: 설명`, 켜진 에이전트마다 목록 한 줄.
- SessionStart 훅이 넣은 글자 수 평균.

"안 쓴 양" = 30일 사용 0회인 스킬·명령·에이전트 목록 줄의 합.

## 6. 연결 그래프와 연결 누수

md 문서가 AI에게 닿는 길을 그래프로 본다.

- 노드: 지시문(CLAUDE.md, AGENTS.md), 메모리 목차(MEMORY.md), 메모리 파일. (스킬·에이전트는 매번 실리는 목록으로 늘 닿으므로 노드에 넣지 않고, 사용 여부만 다른 진단에서 본다.)
- 출발점: 매번 실리는 지시문과 MEMORY.md.
- 길(선) 종류: `목차`(MEMORY.md 의 링크나 이름 적기), `링크`(`[제목](파일.md)`, `[[이름]]` 이 있는 파일로 풀릴 때), `import`(`@경로`), `언급`(본문에 다른 md 파일 이름이 나옴).
- 깊이: 출발점에서 길을 따라 몇 번 만에 닿는가(BFS).

연결 누수 네 종류
| 누수 | 정의 |
|---|---|
| 길 없음 | 어떤 출발점에서도 닿지 않는 md 파일 |
| 끊긴 링크 | `[제목](파일.md)` 대상 파일이 없음. `[[이름]]` 은 아직 없는 메모리를 미리 가리켜도 되는 표시라 세지 않는다 |
| 길은 있는데 안 읽힘 | 닿을 수 있지만 30일 동안 한 번도 Read 되지 않은 메모리 파일 |
| 매번 실리는데 안 쓰임 | 5절의 "안 쓴 양" |

이 PC 실측(2026-11-01): md 256개, 출발점 8개, 1단계 192개, 2단계 4개, 길 없음 52개, 길 없는 52개 중 30일 읽힘 0개, 길은 있는데 안 읽힌 메모리 131개.

## 7. 진단 규칙

분류(`category`): 위험, 고장, 연결 누수, 낭비, 헷갈림.
심각도(`severity`): 높음, 중간, 낮음. 위험은 늘 맨 위에 따로 둔다.

| 규칙 | 분류 | 조건 | 심각도 |
|---|---|---|---|
| secret-in-file | 위험 | 개인·프로젝트 md 파일(지시문, 메모리, 작업 설명서, 명령, 에이전트)에 토큰·키로 보이는 값(redactSecrets 가 가리는 꼴)이 있음. 플러그인 파일은 사용자가 고칠 수 없고 대개 예시 값이라 뺀다. 파일과 줄 번호만 남기고 값은 저장하지 않는다 | 높음 |
| memory-index-truncated | 고장 | MEMORY.md 가 200줄 초과 | 높음 |
| failing-hook | 고장 | 기록에 남은 실패 3번 이상이면 높음, 1~2번이면 중간 | 높음·중간 |
| broken-link | 연결 누수 | 6절 끊긴 링크 | 중간 |
| unreachable-md | 연결 누수 | 6절 길 없음 (v1 orphan-memory 를 대신한다). 메모리 폴더마다 1건 | 중간 |
| unread-md | 연결 누수 | 6절 길은 있는데 안 읽힘. 메모리 폴더마다 1건 | 낮음 |
| memory-index-near-limit | 낭비 | MEMORY.md 180~200줄 | 낮음 |
| unused-plugin | 낭비 | 켜진 플러그인의 스킬·에이전트·서비스를 30일 동안 하나도 안 썼고 자동 실행 규칙도 안 돌았음 | 중간 |
| unused-items | 낭비 | 켜진 스킬·명령·에이전트 중 30일 0회, 출처마다 1건 | 낮음 |
| long-skill | 낭비 | SKILL.md 본문 20,000자 초과 | 낮음 |
| duplicate-rule | 낭비 | 정규화한 같은 줄(25자 이상)이 지시문·MEMORY.md 2곳 이상 | 중간 |
| slow-hook | 낭비 | 평균 3초 이상 또는 최대 10초 이상 | 중간 |
| duplicate-name | 헷갈림 | 같은 이름의 스킬·에이전트가 출처 2곳 이상에 켜짐 | 중간 |
| similar-description | 헷갈림 | 켜진 스킬 두 개의 설명 단어 Jaccard 0.5 이상 | 낮음 |
| missing-description | 헷갈림 | 설명이 없는 스킬·에이전트 | 중간 |

`history`·`builtin` 출처 항목은 설명 기반 규칙(similar, missing, duplicate-name, unused)에서 뺀다.

각 진단이 가지는 것
- `title`(무엇이), `why`(왜 중요한지), `fix`(규칙 공통 한 문장), `evidence`(숫자 근거), 관련 항목 id.
- `steps`(그 항목에 맞춘 순서대로 할 일), `prompt`(Claude Code에 붙여 넣을 요청문), `command`(있으면).
- `gain`(얻는 것): 숫자로 표현할 수 있으면 숫자로. 예: 대화마다 줄어드는 A4 쪽수, 길 없음이 줄어드는 개수, 없어지는 실패 수.
- `fixKind`: `mechanical`(앱이 바로 함), `claude`(`claude -p` 로 함), `manual`(플러그인 파일 등 사용자가 하거나 제보만).

## 8. 고치기

### 8-1. 흐름

할 일의 "고치기" → 미리 보기 → "적용하기" → 백업 → 반영 → 자동 다시 점검 → 결과(전후, 기대 대비 실제) → 되돌리기 가능.
미리 보기 단계에서는 실제 파일이 하나도 바뀌지 않는다.

### 8-2. 종류별 방법

| fixKind | 대상 | 방법 |
|---|---|---|
| mechanical | unused-plugin, 플러그인 단위 unused-items, 플러그인 훅의 slow·failing | `claude plugin disable <이름@마켓>`. `claude` 가 없으면 `C/settings.json` 의 `enabledPlugins` 값을 false 로 바꾼다(백업 후) |
| mechanical | 개인 unused-items, unread-md | 고른 파일·폴더를 `HOME/.claude-checkup/off/<C 기준 상대 경로>` 로 옮긴다. Claude Code 가 읽지 않는 곳이다 |
| claude | memory-index-truncated·near-limit, unreachable-md, broken-link, `C` 안 파일끼리의 duplicate-rule, 개인 long-skill, 개인 missing·similar-description | 8-3절 |
| manual | 플러그인 안 파일의 long-skill, missing·similar-description | 고치지 않는다. 플러그인 끄기 제안과 "만든 사람에게 보낼 제보 문구" 복사만 |
| manual | 개인 훅의 slow·failing | 훅 스크립트는 `C` 밖에 있을 수 있고 하네스 해석은 비목표라 고치지 않는다. 설정 위치 열기, 명령 복사, 맡길 말 복사 |
| manual | `C` 밖 파일(프로젝트 CLAUDE.md·AGENTS.md)이 낀 duplicate-rule | 사용자 저장소 안 파일이라 고치지 않는다. 맡길 말 복사 |
| manual | duplicate-name | 어느 쪽을 남길지는 사용자 판단이다. 두 항목의 사용 횟수를 나란히 보여 주고 맡길 말 복사 |
| manual | secret-in-file | 값을 Claude에게 보내면 안 되므로 `claude` 고치기를 쓰지 않는다. 파일 위치 열기와 줄 번호만 보여 주고, 사용자가 지운 뒤 다시 점검하게 한다 |

여러 항목이 묶인 진단(unused-items, unreachable-md, unread-md)은 미리 보기에서 항목 체크 목록을 보여 준다. 기본은 모두 선택, 사용자가 뺄 수 있다. API 는 `{ findingId, itemIds }` 를 받는다.
첫 화면 할 일 후보와 고치기 버튼은 fixKind 가 mechanical 이나 claude 인 진단만이다. manual 진단은 전체 진단 화면에서 "직접 하는 순서"와 맡길 말 복사만 보여 준다.

#### unreachable-md 고치는 방향

길 없는 파일을 목차에 그대로 다 넣으면 MEMORY.md 200줄 한도를 넘길 수 있다. 그래서 요청문은 이렇게 시킨다.
1. 파일마다 계속 쓸 만한지 판단한다. 오래되거나 다른 파일과 겹치는 것은 "보관 후보"로만 표시하고 고치지 않는다(보관은 앱이 mechanical 로, 사용자가 체크한 것만).
2. 계속 쓸 파일은 MEMORY.md 여유 줄(180줄까지) 안이면 한 줄씩 넣는다.
3. 여유가 모자라면 주제별 하위 목차 파일 하나를 새로 만들고 MEMORY.md 에는 그 파일로 가는 한 줄만 넣는다(새 파일 생성 허용, 같은 메모리 폴더 안만).
미리 보기에서 새로 고장(높음) 진단이 생기면 적용 버튼을 막고 이유를 보여 준다. 그 밖에 나빠지는 지표는 "치르는 것"으로 보여 주고 적용은 허용한다.

### 8-3. `claude -p` 실행

- 쓰기 범위: `C` 안 파일만, `C/plugins` 아래는 제외. 경로 기준 루트는 `C` 다(임시 폴더, 백업, manifest 모두 `C` 기준 상대 경로).
- 대상 파일(메모리 작업이면 그 메모리 폴더 전체)을 임시 폴더에 같은 상대 경로로 복사한다. 이름이 비밀 꼴인 파일과 본문에 비밀값이 있는 파일은 복사하지 않는다. 고칠 대상 파일 자체에 비밀값이 있으면 그 고치기는 manual 로 바꾸고 secret-in-file 을 먼저 해결하라고 안내한다.
- 임시 폴더를 작업 폴더로 `claude -p` 를 실행한다: `--restricted`(파일 도구를 작업 폴더 안으로 가두고 사용자 설정을 읽지 않음), `--strict-mcp-config`, `--tools Read,Edit,Write,Glob,Grep`, `--disallowedTools Bash`, `--permission-mode acceptEdits`, `--no-session-persistence`, `--output-format json`, `--settings`(disableAllHooks), 적당한 `--max-turns`. 요청문은 명령줄이 아니라 stdin 으로 보낸다. 실행 뒤 Claude Code 가 `~/.claude/projects` 에 만드는 빈 폴더는 지운다.
- 요청문은 진단의 `prompt` 를 임시 폴더 경로 기준으로 바꾼 것이다. 비밀값은 싣지 않는다.
- 끝나면 임시 폴더와 원본을 비교해 바뀐 파일과 줄(diff)을 만든다. 임시 폴더 밖이나 대상 밖 파일이 바뀌었으면 그 안은 버리고 경고한다.
- `--bare` 는 API 키 로그인만 지원해 구독 사용자가 못 쓰므로 쓰지 않는다. 실측(2026-11-01): `--restricted` 로 작업 폴더 밖 읽기·쓰기가 막히고, 1회 비용이 약 0.55달러에서 0.01~0.04달러로 줄었다.
- `claude` 가 없거나 로그인돼 있지 않거나 실패하면, 미리 보기 대신 지금의 "Claude에게 맡길 말 복사"와 "직접 하는 순서"를 보여 준다.
- 처음 `claude` 고치기를 쓸 때 "이 기능은 해당 파일 내용을 Claude에게 보내요. 평소 Claude Code를 쓸 때와 같아요"를 알리고 동의를 받는다. 설정에 저장한다.
- 실행 전 예상 사용량(대상 파일 크기 기반 추정)을 보여 주고, 끝나면 json 출력의 실제 사용량을 보여 준다.

### 8-4. 기대 효과 계산

미리 보기의 숫자는 추측이 아니라 계산값이다.
변경안을 원본 위에 덮어씌운 가상의 홈으로 스캐너를 다시 돌리고(실제 파일은 그대로), 전후 지표를 비교한다.
- 비교 지표: 대화마다 미리 채워지는 A4, 안 쓴 A4, 길 없음 수, 끊긴 링크 수, MEMORY.md 줄 수, 진단 수(분류별), 대상 파일 글자 수.
- 화면에는 좋아지는 것(초록)과 치르는 것(주황)을 같이 쓴다. 예: 목차에 25개를 넣으면 길 없음 52 → 27개, 대신 대화마다 A4 +0.6쪽.
- mechanical 은 변경 결과가 확정적이라 같은 방법으로 바로 계산한다(사용량 0).
- 꺼지는 기능 목록(플러그인 끄기)과 그 30일 사용 횟수를 함께 보여 준다.

### 8-5. 적용과 되돌리기

- 적용 직전에 원본이 미리 보기 이후 바뀌었는지(해시) 확인한다. 바뀌었으면 적용하지 않고 미리 보기를 다시 만들게 한다.
- 원본을 `HOME/.claude-checkup/backups/<시각>/<상대 경로>` 로 복사하고 `manifest.json`(무엇을, 어디서, 어떤 방법으로)을 남긴다.
- 반영 후 다시 점검하고, 결과 화면에 전후와 기대 대비 실제를 보여 준다.
- 되돌리기: manifest 대로 원본을 되돌리고, 플러그인 끄기는 다시 켠다. 되돌린 뒤에도 다시 점검한다.
- Claude Code를 다시 시작해야 적용되는 변경은 그렇다고 알린다.

## 10. 구조

- 런타임 Bun, TypeScript. `src/shared/types.ts` 가 유일한 계약.
- `src/scan/`: 순수 함수 스캐너. 가상 덮어쓰기(overlay)를 받아 미리 보기 계산에 재사용한다.
- `src/fix/`(새로): 고치기 실행기(mechanical, claude), 임시 폴더, diff, 백업·manifest·되돌리기.
- `src/server/`: `Bun.serve`, `127.0.0.1`. API 는 types.ts 아래 주석에 둔다. 고치기 API 는 미리 보기 만들기(진행 중 상태 포함), 적용, 되돌리기, 백업 목록.
- `src/ui/`: React 19 + TSX, Bun HTML 번들. Hearth CSS.
- 기록: `HOME/.claude-checkup/history.json` 에 점검마다 요약 지표(전후 비교용)를 남긴다.
- 배포: 소스는 GitHub 공개. GitHub Releases 에 운영체제별 단일 실행 파일(Windows x64, macOS arm64·x64, Linux x64). 코드 서명은 다음 판.
- 테스트: `bun test`. 스캐너·고치기는 `test/fixtures` 가짜 홈으로, `claude -p` 는 가짜 실행 파일로 검증한다.

## 11. 보안·개인정보 (코드 리뷰 2026-11-01 반영)

- `/api/item-body` 와 모든 본문·요약·개요·훅 명령·진단 문구에 비밀값 가리기를 적용한다.
- 훅 이름과 id 는 가린 명령으로 만든다. 가리기 꼴에 URL 사용자 정보, URL 경로 안 긴 토큰, `Basic <값>`, Telegram 봇 토큰, Slack 웹훅 경로를 더한다.
- 접근 키: 첫 접속 1회만 `?key=` 를 받고 쿠키로 바꾼 뒤 키를 폐기한다. 쿠키 이름에 포트를 넣는다(여러 번 실행해도 서로 안 깨짐).
- 응답 헤더: `X-Frame-Options: DENY`, `Content-Security-Policy: frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`.
- 고치기 API 는 쓰기 요청이라 Origin 검사를 그대로 받는다. 클라이언트는 항목·진단 id 만 보내고 경로는 보내지 않는다.
- UI: API 응답이 성공이 아니면 진행 상태로 착각하지 않는다. 잘못된 주소에서도 화면이 비지 않게 최상위 오류 경계를 둔다.
- 공개 전: 개발용 가짜 데이터(`src/ui/dev/`)를 일반 이름으로 바꾸고, 이력 없는 새 저장소로 옮긴다(현재 이력에 실제 이름·경로·이메일이 있다).
